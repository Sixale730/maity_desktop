# Plan-agent adversarial review of draft #83 design (2026-09-23) — key findings to merge into the spec

P0
1. LOGOUT SUPPRESSES JORNADA FOR THE REST OF THE DAY (live bug): logout_cleanup (lib.rs:157-169) -> graceful_shutdown_before_exit -> close_owned_segment_for_exit (service.rs:393-407) -> close_scheduled (service.rs:782); every exit branch of close_scheduled sets rearm_at = start_of_next_day (L810/841/899). Logout+login same day => jornada suppressed until midnight, UI says "siguiente hora en punto". Fix: rearm_at: Option<Rearm{until, cause}> with cause UserStop(L689) | AutoClose(L810/841/899 from evaluate_tick) | RotationRace(L939) | ExitOrLogout; pass cause into close_scheduled; close_owned_segment_for_exit(cause) clears rearm on logout. B4 persistence must persist only UserStop/AutoClose.
2. Drain: emit_event already notify_one() (emit.rs:131) -> loop posts the row within ms; a concurrent flush double-posts (RPC doesn't dedupe). Mutex around drain_once makes flush wait up to 50 posts × 30 s (DEFAULT_TIMEOUT api/http.rs:33). Oldest-first LIMIT 50 (recording_log.rs:70) + rejected-4xx rows retried forever at head. Fix in drain.rs (keeps lint (a)): static INFLIGHT Mutex<HashSet<i64>>; drain_once skips claimed ids; flush_row(id, deadline): synced->done, claimed by loop->wait, else claim+post with .timeout(remaining)+mark. emit_event_id(..)->Option<i64> (log_event returns id recording_log.rs:35; write_to_outbox discards it emit.rs:114).
3. "no ExitRequested => WM_ENDSESSION" incomplete: WM_QUIT (GetMessageW false -> loop_destroyed, tao event_loop.rs:255-257,283-284); muda PredefinedMenuItem::Quit posts PostQuitMessage (muda-0.19.1 windows/mod.rs:1224-1225) — tray uses only separators today (tray.rs:540,551). Silent paths: NSIS process::exit (updater.rs:865), AppHandle::restart from main thread, single-instance 2nd (windows.rs:94), TerminateProcess/taskkill /F/MSIX uninstall. LoopDestroyed fires once (runner.rs:307). Fix: record raw signals {own_reason, exit_requested_code null|0|MAX, sm_shuttingdown bool}; pure resolve_exit_reason(); GetSystemMetrics needs Win32_UI_WindowsAndMessaging (windows 0.58, Cargo.toml:272-296).
4. Exit handler: block_on safe (main thread not tokio worker). Budget problem. Write exit.begun_at sync before block_on; outbox insert under timeout(500ms); graceful stop; write exit.done_at (gap = killed while saving). sm_shuttingdown => marker only no network. External close (sm=0, Restart Manager) => join!(graceful_stop, flush_row(1.5s)) — only way uninstall-while-running becomes visible. Optionally shorten 30 s backstop on shutdown.
5. no_session never observable (both heartbeats gated: JS healthHeartbeatService.ts:178-179, native mem_sampler.rs:300-302; drain defers drain.rs:68-74). SidebarFooterV5.tsx:36-39 signs out WITHOUT logout_cleanup -> current_user_id stays set, has_session true -> JORNADA KEEPS RECORDING AFTER LOGOUT, cloud_sync_clear_session never called. Fix: logout_cleanup emits auth.logout first + flush_row(3s) in parallel with graceful stop, before cloud_sync_clear_session (AuthContext.tsx:905-913); SidebarFooterV5 -> useAuth().signOut(); when !has_session && jornada enabled emit native heartbeat hourly with session:false (outbox, uploads at next login with real occurred_at).
6. Offline hours: JS heartbeats direct RPC no retry (platformLogger.ts:100); record_js_snapshot marks alive before delivery (commands.rs:351) suppressing native (mem_sampler.rs:353-367) -> visible window + no network = zero durable beats. Fix: on-device per-day summary jornada.day_summary (seconds per idle_reason bucket, accumulated in marker each sampler tick, emitted via outbox at local midnight or next boot).
