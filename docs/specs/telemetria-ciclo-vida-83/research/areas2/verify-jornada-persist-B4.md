# Verdict: needs_changes

## Issues
- [major] Headline invariant: SessionEnd never reaches disk, so exiting, logging out, a rival install or powering off never suppresses the jornada after a restart. Risk 2 mitigation says the in-memory hold covers the exit window.
  - Evidence: The recording's `is_rec` turns false at the START of the stop, not when the stop finishes. `is_recording_active_fn` = `recording_phase::current_phase().is_session_active()` (recording_lifecycle.rs:47-48), and `is_session_active` is `matches!(self, Recording | Paused)` (recording_phase.rs:61-62), so it is false during `Stopping`. Meanwhile `close_scheduled` keeps `owned == true` until step 5 (service.rs:896). In between it runs stop_current_recording (drain and encode) and finalize_segment_native (service.rs:804, 847), which can take seconds. The exit path runs close_scheduled from ANOTHER task (lib.rs:1840 via tray.rs:65 spawn, or RunEvent::Exit block_on at lib.rs:1789). The loop keeps ticking on the multi-thread runtime: tauri async_runtime.rs:223 `TokioRuntime::new()`, and nothing in the repo calls `async_runtime::set`. A tick in that window sees owned=true, !is_rec and in-window, takes the `(true, Some)` arm (service.rs:686-692) and, under the spec, `release_after_external_stop` → `set_rearm(Some(Rearm::user_stop))`, which PERSISTS. Step 5 would later overwrite this with SessionEnd and delete the file only if (a) close_scheduled reaches step 5 and (b) the tick's write did not land after step 5 (TOCTOU: the tick reads `owned` at L514 and writes after awaits). Step 5 is never reached when timeout(30s) at lib.rs:1793 or timeout(60s) at tray.rs:67 drops the future, or when Windows kills the process in WM_ENDSESSION (B5). Then the file keeps user_stop and, after the reboot, the jornada stays suppressed until the next o'clock hour. rotate_scheduled has the same problem: at L929-939 its Ok(false) branch treats the exit-path stop that won the StopGate as a user stop and writes next_hour_boundary, which would also persist.
  - Fix: Add `session_ending: Arc<AtomicBool>` to SchedulerShared. A new method `begin_session_end()` sets it together with the in-memory `Rearm::session_end(now)` hold. Call it as the FIRST statement of graceful_shutdown_before_exit, before the stop, even when nothing is recording, so it covers tray quit, RunEvent::Exit, logout_cleanup, rival_install and whatever B5 adds. While the flag is set: (1) `set_rearm` never writes UserStop/AutoClose to disk, only to memory; (2) the `(true, _)` `!is_rec` arm and the Ok(false) arms of rotate/close do not overwrite a SessionEnd hold. Clear the flag when the hold is released (no session or the 15-minute cap). Add a unit test that fixes the rule 'with session_ending=true, serialize never happens for any cause', and an E2E check with a slow finalize (a long recording, exiting just before a tick).
- [major] §8 observe_stop_before_exit is idempotent with the tick, safe, and 'No-op si no somos dueños o si sigue grabando'.
  - Evidence: The check is `owned && !is_recording_active_fn()`. That is also true while the tick is in the middle of a rotation: rotate_scheduled stops (Stopping, is_rec=false), finalizes (L969) and restarts (L1003), with owned=true the whole time. It is also true on the second graceful call in RunEvent::Exit after the tray's 60 s timeout dropped the first close_scheduled after its stop but before step 5 (owned still true, not recording). In both cases observe_stop persists a UserStop from what was only an exit. In the rotation case it also sets owned=false in the middle of rotate_scheduled; the restart at L1011 then sets it back to true. The current graceful path returns early (`if !is_recording()` L1834) during a rotation, so there is no SessionEnd hold to counter it. Result: exiting or powering off at the top of the hour suppresses the jornada until the next hour after the reboot.
  - Fix: Add an in-flight transition flag, e.g. `transition_in_flight: AtomicBool` with an RAII guard set for the whole body of close_scheduled and rotate_scheduled. observe_stop_before_exit is a no-op while it is set or while `session_ending` is set (the previous issue). With `begin_session_end()` running first, run observe_stop BEFORE setting session_ending, and only when there is no transition in flight. Alternatively, drop §8: it is marked optional, and losing an unobserved user stop fails open.
- [minor] Graceful exit during a tick-driven auto-close: AutoClose is persisted, so the day stays closed after a restart.
  - Evidence: If the tick is inside close_scheduled (AutoClose) when the exit arrives, graceful_shutdown_before_exit sees `!is_recording()` (Stopping or already Idle during finalize) and returns at lib.rs:1834-1835. RunEvent::Exit then goes on to `db_manager.cleanup()` (lib.rs:1806) and the process dies before step 5 (L899). AutoClose is never persisted, so the reboot restarts an overtime segment. The DB-pool-closed-under-finalize hazard already exists today and is outside B4, but the spec's promise that the closed day survives a restart does not hold on this path.
  - Fix: Document it as fail-open, or have graceful wait for `transition_in_flight` to clear (bounded) before returning. That also protects the in-flight finalize from the pool cleanup, and should be coordinated with B5/T2.
- [minor] The SessionEnd hold is released 'en cuanto el loop ve que ya no hay sesión (tope de 15 min)', and exit, logout and rival install all end the process or the session.
  - Evidence: In rival_install.rs:78-104, graceful runs first, then `launch_detached_uninstaller(...)?` can fail and the app stays '100% funcional' (comment L66-67). The session stays alive, so the SessionEnd hold lasts the full 15 minutes and the jornada does not restart during that time. This is better than today's start_of_next_day, but it is not documented. With the previous fix (the session_ending flag), the flag would also stay set.
  - Fix: On the rival_install error path, call something like `cancel_session_end()` to clear the hold and the flag, or document the 15-minute bound explicitly in the ONBOARDING_Y_GATES section.
- [minor] set_rearm reflects to disk 'SOLO si cambió'; SessionEnd/None ⇒ the file is deleted.
  - Evidence: On every exit with an owned segment, prev=None → SessionEnd counts as a change, so set_rearm takes persist_lock and runs `tokio::fs::remove_file` (a spawn_blocking round-trip) inside the RunEvent::Exit block_on. Under B5 that is inside WM_ENDSESSION. While owned, no live persisted suppression can exist: the tick never starts before `until`. The I/O is useless and sits on the power-off critical path.
  - Fix: Hit the disk only when the persistable projection changes (`serialize_state(prev) != serialize_state(new)`). None → SessionEnd then does no I/O.
- [minor] B4 is self-contained; conflicts with T2/B5 in graceful_shutdown_before_exit are only textual merge conflicts.
  - Evidence: If B5 changes the WM_ENDSESSION path to stop the recording quickly without the full close_scheduled (for example a stop plus checkpoints), the tick-race window from the first issue gets wider: owned=true, is_rec=false, no step 5. The protection depends on B5 also calling `begin_session_end()` first.
  - Fix: State in depends_on/risks that every exit path added by B5/T2 must call `begin_session_end()` before any stop, and add a line to the ONBOARDING_Y_GATES section: 'toda ruta de salida marca session_ending ANTES de detener'.

## Confirmed claims
- There are exactly 7 writers of rearm_at, all in service.rs: 604 and 674 clear it when it expires, 689 and 939 set next_hour_boundary, and 810, 841 and 899 set start_of_next_day. No writers outside service.rs.
- rearm_at is in memory only: it is initialized to None at service.rs:271, and initialize (service.rs:303-308) loads only settings.
- close_owned_segment_for_exit (service.rs:393-407) reuses close_scheduled, so the exit path sets start_of_next_day today (L899).
- graceful_shutdown_before_exit (lib.rs:1833-1861) is the common funnel for tray.rs:69, logout_cleanup (lib.rs:161), RunEvent::Exit (lib.rs:1795) and rival_install.rs:78. It returns early on !is_recording() without checking ownership.
- Latent bug: after a logout with the jornada active plus a new login in the same process, the jornada stays suppressed until midnight. The rearm check (L597-606) comes after the NoSession/registration gates (L585-595), which contradicts the comment at L581-584 and ONBOARDING_Y_GATES.md:10.
- The in-memory exit hold is needed. The tauri runtime is multi-thread (tauri-2.11.2 async_runtime.rs:223 TokioRuntime::new(), and the repo never calls async_runtime::set), so the loop ticks during the RunEvent::Exit block_on. The spec's 'UNVERIFIED' note on this is now verified.
- The scheduler is initialized in a spawned setup task under the service write lock, before start() and only if enabled (lib.rs:1370-1395). initialize_scheduled_recording (commands.rs:18) has no callers and is not a registered command.
- start_of_next_day is private at service.rs:714-718. next_hour_boundary is public at schedule.rs:77-84 and returns strictly the next hour (tests at L251-264).
- start_backoff is in memory only (service.rs:260). UpdateSettings and CheckNow clear only start_backoff (L480, L486), never rearm.
- catch_up_on_start is never read by the service. It appears only in settings.rs (declaration, default, tests) and the TS type.
- chrono has the serde feature (Cargo.toml:92), tempfile is a dev-dependency (Cargo.toml:321), and tokio::fs is already used in scheduled_recording (settings.rs:155/208), so the fs feature is available transitively.
- The docs bullet at ONBOARDING_Y_GATES.md:23 mentions `rearm_at` and needs updating. The back-off section ends at :27.
- No new telemetry events or Tauri events are added, so lint-telemetry, lint-tauri-events and lint-tauri-acl are unaffected.

## Corrected design notes
Keep the core design: Rearm{until,cause,set_at}; only UserStop and AutoClose are persistable; SessionEnd lives only in memory; a separate runtime JSON with atomic tmp+rename; pure restore() validation; start_of_next_day moved to schedule.rs; no persisted backoff. The following corrections are required.

(1) Add `session_ending: Arc<AtomicBool>` to SchedulerShared and a public `begin_session_end(app)` on the service. It sets the flag, then `*rearm = Some(Rearm::session_end(now))` in memory, with no disk I/O. Call it as the FIRST statement of graceful_shutdown_before_exit, before the `!is_recording()` early return, so it covers tray quit, RunEvent::Exit, logout_cleanup, rival_install and any B5 path. While the flag is set:
- set_rearm must not persist any cause;
- the `(true, Some)`/`(true, None)` `!is_rec` arms must not replace a SessionEnd hold with UserStop (they can still release ownership);
- the Ok(false) branches of rotate_scheduled (L939) and close_scheduled (L810) must keep the SessionEnd hold.
Clear the flag and the hold together, when the tick sees !has_session or the 15-minute cap expires. Add a `cancel_session_end()` for the rival_install error path after launch_detached_uninstaller fails.

(2) Add `transition_in_flight: AtomicBool` with an RAII guard over the whole body of close_scheduled and rotate_scheduled. observe_stop_before_exit (§8) must return early when a transition is in flight or session_ending is already set. If it is kept, run it before begin_session_end. Otherwise drop §8: losing an unobserved user stop fails open. Also consider having graceful wait, with a bound, for transition_in_flight to clear before returning. Today an exit during a tick-driven close or rotation returns immediately and lets RunEvent::Exit close the DB pool under finalize, and the AutoClose is never persisted. That is out of scope for B4 but should be documented.

(3) In set_rearm, compare `serialize_state(prev)` with `serialize_state(new)` and touch disk only when they differ, so None→SessionEnd costs no I/O inside WM_ENDSESSION.

(4) Tests to add:
- a pure 'with session_ending set, nothing persists' policy test;
- a test that rearm_for_close(SessionEnd) serializes to None (already planned);
- a test that the `(true,_)` release under session_ending keeps SessionEnd, via a pure decision fn like `fn rearm_after_external_stop(current: Option<Rearm>, in_window, session_ending, now) -> Option<Rearm>`.

(5) Manual E2E: with a long streaming segment (slow finalize), quit from the tray right before a 30 s tick and verify no user_stop file remains. Also exit exactly at hh:00 during a rotation.

(6) Docs: add a 'no revertir' rule: every exit path calls begin_session_end() before stopping. Also document the 15-minute hold after a failed rival uninstall.
