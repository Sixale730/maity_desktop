# Verdict: needs_changes

## Issues
- [major] All three close_scheduled rearm writes (service.rs:810, 841, 899) are auto-close and should carry RearmCause::AutoClose, mapping to SkipReason::ClosedForDay. The spec also tells the B4 owner to persist Rearm as-is.
  - Evidence: close_scheduled is also reached from the exit/logout path, not only from auto-close. service.rs:393-406 `close_owned_segment_for_exit` calls `close_scheduled(app, &self.shared, &settings, since, now).await`. That is called from lib.rs:1840 `graceful_shutdown_before_exit`, which is called from logout_cleanup (lib.rs:158-161), tray quit (tray.rs:69), rival_install.rs:78 and RunEvent::Exit (lib.rs:1795). Logout does not end the process, and the scheduler loop keeps running. Consider a user who logs out inside the window while the jornada is recording, then logs back in (the same account or another one). They get rearm_at = start_of_next_day. The next tick first reports NoSession (L585-586), and after re-login it reports the rearm. With this spec that would be ClosedForDay ("La jornada de hoy ya se cerró") and idle_reason `closed_for_day`, which misclassifies a logout as an auto-close for the rest of the day. B4 makes it worse: if the persisted Rearm is taken from this path, then tray quit at 11:00 followed by reopening at 11:05 suppresses the jornada for the whole day.
  - Fix: Pass the cause into close_scheduled (for example `close_scheduled(..., cause: RearmCause)`). The auto-close call at L547 passes AutoClose. close_owned_segment_for_exit passes a new `RearmCause::ExitOrLogout` (or `Logout`). Map that cause to its own idle_reason, or better, decide explicitly that the exit/logout path does not set a rearm at all (open question for the user). Tell the B4 owner that exit/logout rearms must NEVER be persisted. Add a test showing that the exit path never produces ClosedForDay.
- [major] The idle_reason value `transcription_not_ready` and `backoff.kind` `other` line up with the recording_start_failed.code values, so the data supports the 'no mic/permission' category.
  - Evidence: `StartFailureKind::Other.skip_reason()` returns `SkipReason::TranscriptionNotReady` (service.rs:171). `record_start_failure` returns `kind.skip_reason()` (service.rs:1761) on every failure. `classify` (L157-163) folds MicInUse, MicFormatUnsupported and Unknown (audio_unknown, including funnel rejections) into Other. So the first failure of any non-mic/permission start, such as the mic being held by another app, is reported as `transcription_not_ready`, and the spec's table maps it to idle_reason `transcription_not_ready`. The device_errors.rs:89-95 codes (`mic_in_use`, `mic_format_unsupported`, `audio_unknown`) are lost.
  - Fix: Store the stable code in StartBackoff (`code: &'static str` from `classify_device_error(raw).code()`; it is Copy). Expose `backoff.code` in JornadaTelemetry and give idle_reason a `start_failed` value (with the code next to it) instead of `transcription_not_ready`. Alternatively, keep the skip string for UI compatibility but never turn it into idle_reason without backoff.code. Update the IDLE_REASONS domain and the T5 SQL to match.
- [minor] device.profile carries the jornada config (1× per session); None only means 'not initialized yet'.
  - Evidence: healthHeartbeatService.ts:189-197 emits device.profile once, on the first post-session tick, with a latch. The scheduler's initialize runs in a spawned task from setup (lib.rs:1372-1381) that first has to take `write()` on the outer lock. If it has not published yet, `jornada: null` is emitted and never refreshed for that process.
  - Fix: Either retry the profile emission (do not set the latch) while `jornada` is null, bounded to a few ticks, or document that `health.heartbeat.jornada.enabled` is the authoritative per-beat source and that device.profile.jornada may be null. T5's SQL should prefer the heartbeat block.
- [minor] `no_session` is a meaningful idle_reason in the closed table.
  - Evidence: The JS heartbeat returns early without a Supabase session (healthHeartbeatService.ts:178-179). The native heartbeat is gated by `crate::state::has_session` (mem_sampler.rs:300-301), which is the same predicate as SkipReason::NoSession (service.rs:585). So `no_session` can only show up in a skew window between the Supabase session and the Rust current_user.
  - Fix: Keep the value but document in TELEMETRIA.md and the T5 SQL that logged-out days produce NO heartbeats. They fall into 'no signal' and are not a `no_session` idle_reason, so T5 needs the auth.logout event (T4) for that category.
- [minor] The ClosedForDay message 'La jornada de hoy ya se cerró; la grabación se reanudará en tu siguiente horario' is always truthful after auto-close.
  - Evidence: start_of_next_day (service.rs:714-718) is midnight. For a cross-midnight window (for example 22:00-06:00) with auto_close 23:30, the rearm expires at 00:00 while is_within_window is still true for the post-midnight part (schedule.rs:52-55), so the jornada restarts 30 min later. For a 06:00 close inside a night window, the same evening's window is suppressed. Both behaviors are pre-existing.
  - Fix: This is acceptable for B3 but should be listed in open_questions (the spec already names the second case). Consider making the rearm deadline `schedule::next_fire_at` after the current window instead of midnight in a follow-up.
- [minor] L806 (the user won the StopGate at close time) is correctly AutoClose.
  - Evidence: The same Ok(false) branch (service.rs:805-811) also runs when close_scheduled is invoked from close_owned_segment_for_exit (logout/quit) and the user stopped first. The cause must come from the caller, not from the branch.
  - Fix: This is covered by the cause-parameter fix in issue 1: every write site in close_scheduled uses the caller-provided cause.

## Confirmed claims
- rearm_at writes: service.rs:689 next_hour_boundary (user stop in window), 810/841/899 start_of_next_day inside close_scheduled, 939 next_hour_boundary (rotation race); field at L252.
- The in-window arm (service.rs:598-605) turns any pending rearm into SkipReason::RearmingNextHour, whose message (L98-100) promises 'la siguiente hora en punto'. That is B3 when auto_close_time falls before the window end.
- The windows are half-open [start,end) (schedule.rs:36-57). With the default 09-18/18:00, the close lands in the idle arm (service.rs:668-683), which returns (Idle, None).
- The skip reason is loop-local (prev_skip, service.rs:432, 456-461) and reaches the UI only as the scheduled-recording-skipped event; ScheduledRecordingIndicator.tsx:33-36 shows only `message`.
- Every inner SchedulerShared read is a snapshot in its own statement; the grace_deadline guard block (L529-536) has no await. Adding Copy reads right after L450 does not violate the lock contract.
- The outer ScheduledRecordingState lock is held read() across a full segment close (lib.rs:1839-1840) and write() across start/stop (commands.rs:64-70, 83, 95) and setup (lib.rs:1376-1391). A process-global std Mutex slot is a sound way to avoid stalling heartbeats (same pattern as mem_sampler LAST_SAMPLE, mem_sampler.rs:293-295).
- get_health_snapshot takes no AppHandle; HealthSnapshot is built in exactly 3 places (commands.rs:364, 493, 535).
- emit_native_heartbeat builds its own json! payload (mem_sampler.rs:384-403), gated by should_emit_native_heartbeat && has_session (L300-301).
- The JS heartbeat picks its fields explicitly (healthHeartbeatService.ts:211-233); device.profile is spread once per session (L189-197). get_device_profile has one literal (commands.rs:454), plus a consumer in incident.rs:327.
- update_settings (service.rs:345-358) is the only persistence chokepoint (commands.rs:42, 59); no other writer of scheduled_recording_settings.json exists.
- in_window in get_status/emit_status ignores enabled (service.rs:371, 1634); idle_unload::window_context gates on enabled (idle_unload.rs:143-154).
- rotate_scheduled discards record_start_failure's reason (service.rs:1025-1026), and evaluate_tick returns (phase, None) (L572-573).
- Every pause_recording caller is a user action (tray, coach-float, widget, RecordingControls, recordingService); there is no automatic pause.
- tokio is 1.49.0 (Cargo.lock). Interval::reset = reset(now+period) and reset_immediately = reset(now), so CheckNow delays evaluation by a full period.
- emit_event signature, TelemetryStatus::Ok and context::process_session_id exist as the spec uses them; the precedent is service.rs:1365-1369.
- chrono has the serde feature (Cargo.toml:92); rust-version 1.77, so a const Mutex::new in a static is valid; ScheduleWindow derives only Debug, Clone, Serialize, Deserialize (settings.rs:97), so PartialEq has to be added.
- The doc references are accurate: ONBOARDING_Y_GATES.md:23, TELEMETRIA.md:215-216 (device.profile/heartbeat rows) and 386-392 (cardinality).

## Corrected design notes
B3 must type the cause at the CALLER, not at the write site. Change the signature to `close_scheduled(app, shared, settings, owned_since, now, cause: RearmCause)`. evaluate_tick L547 passes RearmCause::AutoClose. `close_owned_segment_for_exit` (service.rs:405, reached from logout_cleanup lib.rs:158, tray quit tray.rs:69, rival_install.rs:78 and RunEvent::Exit lib.rs:1795) passes a new RearmCause::ExitOrLogout. Only AutoClose maps to SkipReason::ClosedForDay. ExitOrLogout needs a product decision. The recommendation is to NOT set a rearm on that path: the process is ending anyway, and after a logout/login in the same process a re-login inside the window should resume the jornada. If a rearm is kept, give it its own idle_reason (`closed_on_exit`) and tell the B4 owner never to persist it, because tray quit plus reopen must not suppress the day. Add a test that the exit path never yields ClosedForDay or `closed_for_day`.

Telemetry quality: add `code: &'static str` (from `crate::audio::device_errors::classify_device_error(raw).code()`) to StartBackoff in record_start_failure, and expose it as `jornada.backoff.code`. Replace idle_reason `transcription_not_ready` with `start_failed` (code alongside), because SkipReason::TranscriptionNotReady is really 'first failure of kind Other' (service.rs:171, 1761) and covers mic_in_use, mic_format_unsupported and audio_unknown. Keep the SkipReason as_str strings unchanged for UI-event compatibility.

Document for T5 that `no_session` is practically unobservable in heartbeats (both emitters are session-gated), so logged-out days are 'no signal' unless T4's auth.logout is present. Also document that device.profile.jornada may be null if the profile beats the scheduler's initialize, and prefer heartbeat.jornada.enabled per beat (or re-emit the profile while jornada is null).

The rest of the design is sound as specified: the std::sync::Mutex slot with a loop_running gate against late ticks; the Copy snapshot reads after service.rs:450 (no guard held across an await, no outer-lock access); the pure idle_reason; the diff-guarded jornada.settings_changed spawned from update_settings with status Ok and process_session_id; the three lint entries; ScheduleWindow gaining PartialEq; and the report-only CheckNow reset_immediately finding (confirmed against tokio 1.49.0).
