- [major] The classification SQL covers the issue's 'paused by user' category, and 'detenida por el usuario' is a reachable bucket with its own B action ('Reanudar Maity' / 'Dejar Maity grabando toda la jornada').
  - Evidence: The CASE checks `conv_n > 0`, `seg_desc > 0` and `rec_started > 0 or hb_rec > 0` before `hb_pausa > 0` and `motivo = 'stopped_by_user'`. A jornada recording starts every day it runs: evaluate_tick service.rs:621-652 starts it, hourly rotation (service.rs:560-575, rotate_scheduled) restarts it, and auto-close closes it at auto_close_time (service.rs:521-551, close_scheduled). So a day where the user paused or stopped always has recording_started/conversation/segment_discarded and lands in 'grabó' / 'descartado' / 'sin conversación guardada'. stopped_by_user only appears in heartbeats between the stop and the next hour of a day that already had recording_started. The web SKILL.md:162 already notes that paused users in Dingler went back to recording. In practice both buckets fire only when a pause spans midnight with auto_close off.
  - Fix: Put a partial-day signal on recording days. Either add a second column `motivo_parcial` (for example 'pausada' when hb_pausa >= hb_rec, 'detenida por el usuario' when there are stopped_by_user heartbeats in window) or split 'grabó' into 'grabó toda la jornada' and 'grabó parcialmente: pausada/detenida'. ## Corrected design notes
Keep the overall structure: C1 is the contract and lands before T1-T4, C2 fills the placeholders, C3 is the stub. Correct the following.

(1) The query needs a partial-day dimension. Today 'pausada' and 'detenida por el usuario' cannot be reached for jornada recordings, because recording_started / a conversation / segment_discarded always exist on those days (hourly rotation, auto-close). Add `motivo_parcial` (hb_pausa vs hb_rec share, stopped_by_user heartbeats in the window) or split 'grabó' into full and partial, and attach the B actions to it.

(2) Do not infer 'sesión cerrada' from hb=0 alone. JS heartbeats are not queued when offline (TELEMETRIA.md:299), so an offline day with outbox events would be mislabelled. Require auth.logout/session_lost or an outbox-carried idle_reason='no_session'. Otherwise use 'corrió sin latido (sin red o sesión cerrada)'. Consider putting the jornada snapshot on an outbox event too (app.start and/or a Rust jornada.state emitted when idle_reason changes).

(3) Reorder the n_ev=0 branches so a known explicit cause (auth.logout after the last heartbeat, arguably tray_quit) beats 'posible desinstalación'.

(4) The version-fallback branch should be `not ant_nueva`, without `sig_start is null`. Define prev_exit_clean=null as 'no marker (first run or upgrade from <0.2.62)'.

(5) Use days_of_week only when windows_count=1. Join Q11/Q11b by user id, not nombre.

(6) Contract precision:
- idle_reason is null iff scheduler_phase ∈ {recording, grace}. manual_in_progress can coexist with heartbeat phase=recording. closed_for_today/stopped_by_user/rotation_pending come from a cause stored with rearm_at, not from the tick phase (close_scheduled returns Idle inside the window).
- app.exit must map ENDSESSION_CLOSEAPP (Restart Manager, likely used for MSIX updates; UNVERIFIED) to update_restart or a distinct value, never os_shutdown. State the fallback when lParam cannot be captured.
- auth.logout must be awaited (bounded) before logout_cleanup/signOut.
- auth.session_lost must use an explicit outbox path (direct log_recording_event invoke with its own session id, or a Rust command), because recordingLogService.log no-ops without startSession().

(7) B4 doc: CheckNow and saving settings clear only start_backoff (service.rs:478-486), not rearm_at. Do not document them as lifting 'detenida/cerrada por hoy'.

(8) The web side (W1) conflicts with the user's memory rule: 'web-side changes filed as issues in the web repo, never edited from the desktop session'. Confirm with Julio or deliver W1 as a Sixale730/maity issue carrying the full Q11/Q11b/SKILL text. In either case gate it on T1-T4 being merged and on key names verified against real 0.2.62 rows. Avoid 'Implementado en 0.2.62' until the release ships.
